# 나무증권 Strategy B — 청산 로직 안전 수정 (2026-10-14)

대상 저장소: `ewqewq1234-ctrl/kis-bot-v2`, `main`의 2026-10-14 버전.

## 적용할 파일 (세 개만)

- `run_cloud.py` — 청산 허용 조건, 매도 체결 검증, 청산 후 재진입 대기
- `nh_client.py` — 본전 청산 직전 `currentExecution.Output_1.bidp` 검증 추가
- `tests/test_exit.py` — 모의 주문/체결 14개 테스트 추가

**`state.json`, `tokens.json`, `requirements.txt`, `.github/workflows/trade.yml`, 기존 `tests/test_safety.py`는 수정하지 않습니다.** 기존 실행 중인 포지션 32주/4단계 기록은 그대로 보존해야 합니다.

## 수정 내용

1. **당일 매수 후 매도 허용:** 기존 `if orders: return`은 당일 매수도 청산을 차단했습니다. 신규 매수는 오늘 주문이 있을 때 계속 차단하되, 청산은 당일 *매수* 이력만으로 차단하지 않습니다.
2. **중복 매도 방지:** 당일 매도 이력이 1건이라도 있거나 매매구분 필드를 해석할 수 없다면 새 매도를 차단합니다. 잔고 조회 실패/미체결 등은 기존처럼 거래 중단합니다.
3. **3·4단계 본전 청산 가격 보호:** 기존 `평단 +0.05%` 목표가를 **변경하지 않습니다**. 발동 시 최신 최우선 매수호가(`bidp`)를 새로 조회하여, 그 호가가 목표보다 낮으면 주문하지 않습니다. 목표 이상이면 **최우선 매수호가에 지정가 매도**합니다. 지정가는 목표 아래의 즉시 체결을 제한하지만 **미체결 위험이 있으며, 매매 비용을 포함한 순이익은 보장하지 않습니다.**
4. **1·2단계 트레일링:** +2% 트리거, 관측 고점 -1% 반락, 시장가 매도는 **변경하지 않습니다**. 당일 매수 후에도 발동할 수 있습니다.
5. **체결 확정:** 매도 접수 즉시 포지션을 0으로 바꾸지 않습니다. 실계좌 0주 외에 매도 주문일의 당일주문체결조회(`orr_qty`, `tot_cns_qty`, `ny_cns_qty`, `can_qty`)로 **단일 매도 전량체결** 확인 뒤에만 상태를 0단계로 복구합니다. 주문 접수 번호 `mkt_orr_no`와 체결조회 통합주문번호 `itg_orr_no`는 명세상 다른 식별자로, 같다고 가정하지 않습니다. 같은 날 유일한 전량체결 매도라는 보수적 조건으로 검증하며 모호하면 중단합니다.
6. **즉시 재매수 방지:** 청산일과 다음 평일 거래 세션 동안 `last_exit_date`로 신규 진입을 잠시 막습니다. 공휴일 달력은 미포함이므로 공휴일 운영 시 추가 보완이 필요합니다. 기존 분할매수 비중/추가매수 트리거는 변경하지 않습니다.

## 모의 테스트

```bash
python -m compileall -q run_cloud.py nh_client.py
python -m unittest discover -s tests -v
```

기존 11개 + 신규 청산 14개 = **총 25개** 모의 테스트 통과 (로컬 Python 3.13.5). GitHub Actions Python 3.11 및 실제 나무 서버는 아직 이 패치로 검증하지 않았습니다.

## 적용 및 실거래 전 체크

1. **GitHub Actions 자동매매를 일시 중지**하고 진행 중 작업이 없는지 확인하십시오. 기존 미체결/예약주문도 나무 앱에서 확인하십시오.
2. 현재 `state.json`을 백업하십시오. 이 패키지의 수정 대상에 `state.json`은 없습니다.
3. 위 3개 파일을 동일 경로로 업로드/커밋하십시오.
4. `ENABLE_LIVE_ORDERS=NO` 유지 상태에서 GitHub Actions 모의 테스트/실계좌 읽기 조회만 실행하십시오.
5. `tests` 통과, 잔고 동기화, 주문조회 및 호가 조회 API 필드가 실서버에서 올바른지 확인하십시오.
6. 주문 접수와 실제 체결의 구분/중단 알림 및 미체결 처리 절차를 확인한 뒤에만 주문 활성화를 판단하십시오. **이 수정안은 실주문을 실행하거나 ENABLE_LIVE_ORDERS를 YES로 변경하지 않습니다.**

### 운영상의 제한

- GitHub Actions 스케줄은 시간 단위이므로 목표가를 장중 잠시 찍고 내려오면 청산이 실행되지 않을 수 있습니다.
- 3·4단계 지정가 청산은 급락/호가 변경 시 미체결될 수 있습니다. 미체결 상태가 지속되면 자동 재주문하지 않고 안전중단하므로 수동 확인이 필요합니다.
- 매도 체결조회 통합주문번호는 접수번호와 **같다고 가정하지 않습니다**. 매도 내역이 둘 이상이면 자동 포지션 복구를 보류합니다.
- 청산일과 다음 평일의 재진입을 막는 정책은 전략 결과에 영향을 줄 수 있습니다. 이 동작은 명시적으로 검토하십시오.
